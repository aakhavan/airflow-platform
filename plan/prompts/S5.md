# S5: Governor as the first project, end to end

**Commands (permission rules):** run each command as a single `uv run ...` call. Don't use `&&`, `;`, pipes, PowerShell expressions, `uv lock`, `uv sync` or bare `python`/`pytest`. `uv run` locks and syncs by itself. Use: `uv run pytest -q`, `uv run python -m airflow_platform.stack ...`, `uv run python plan/accept/<script>.py`. Docker and Terraform go through the stack module or the acceptance scripts.

Contract: `docs/spec.md` §6 (governor entry) and §8 (S5 part). The governor side (A1) is already merged into the worktree branch `airflow-integration` at `../governor-airflow`. Read its `airflow/dags/governor_profile_raw.py`; **do not change anything there.**

Preconditions (the acceptance checks them; if any fails, stop and write what's missing in `NOTES.md`; do not work around it):
- governor test bed Postgres is up on host port 55432 with the Olist `raw` schema loaded (`../governor/testbed/README.md`);
- image `governor:local` exists (built from the worktree: `docker compose build` in `../governor-airflow`);
- the governor stack (api on 8000, ui on 8501) runs from the worktree.

Build:
1. `projects/projects.yaml`:
   - Remove the S4 placeholder `view` and `task_link` from `examples`.
   - Add `governor` as §6 shows, with `dags.local: ../../governor-airflow/airflow/dags`. Add a YAML comment that after the merge it becomes `../../governor/airflow/dags`.
   - Set `view.url` to `http://localhost:8501` and `task_link.url_template` to the Profiles page with `run_id`, matching how A1's page reads the query param. Read the page file to confirm.
2. Airflow Variables for the DAG: `docker_url`, `governor_data_volume`, `governor_pg_host`, `governor_pg_port`, `governor_pg_db`, `governor_build_user`, `governor_build_password`. Use whatever names A1's DAG actually reads. Set them through `AIRFLOW_VAR_<NAME>` entries in `stack/.env.example`, with the documented local test bed defaults. `.env` is created from it by `stack up` when missing; never read `.env`.
3. `docs/projects/governor.md`: the runbook from §8. It covers the order of start-up, how to trigger `governor_profile_raw`, where the report link is, how to switch to `../governor` after the merge, and troubleshooting (volume name, `host.docker.internal`, proxy sections).
4. `README.md`: a "Projects" section with a one-line example.
5. Run `stack up`.

Tests (offline): `test_registry_has_governor_with_view_and_link`, `test_governor_link_targets_profiles_page`, `test_env_example_has_no_values_beyond_documented_defaults` (an allowlist of names and default values).

Done when `plan/accept/accept_s5.py` passes. It triggers `governor_profile_raw`, waits for success, checks that the profile file exists in the governor volume (through a throwaway `alpine` container that only lists it), checks `GET http://localhost:8000/health`, and checks that the task link URL returns HTTP 200 from Streamlit.
