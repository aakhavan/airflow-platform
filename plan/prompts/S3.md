# S3: projects.yaml to DAG bundles and the compose override

Contract: `docs/spec.md` §6 and §12 (S3 row). Rules: `AGENTS.md`.

Build:
1. Read the Airflow 3.3 docs on DAG bundles: the `LocalDagBundle` class path and kwargs, the config key (`[dag_processor] dag_bundle_config_list`) and which services must see the bundle paths. Record what you found in `NOTES.md`.
2. `projects.py`:
   - `render_bundles(projects, target="local") -> list[dict]`: one `LocalDagBundle` per project, `path=/opt/airflow/projects/<name>`. With `target="cloud"`, use a `GitDagBundle` for projects with `dags.git` (git provider class, kwargs per the docs) and skip local-only projects.
   - `render_compose_override(projects, registry_dir) -> dict`: a read-only bind mount `<abs local path>:/opt/airflow/projects/<name>:ro` for every service the docs say reads bundles, plus `projects/projects.yaml` mounted read-only at `/opt/airflow/projects/projects.yaml` (the plugin reads it in S4). Paths use forward slashes, so Docker Desktop on Windows accepts them.
3. `stack.py render [--projects PATH]` (default `projects/projects.yaml`; `up` takes the same option): writes `stack/.env.generated` (`AIRFLOW__DAG_PROCESSOR__DAG_BUNDLE_CONFIG_LIST=<json>`) and `stack/compose.projects.yaml`. `up` runs `render` first and passes both files (`--env-file stack/.env --env-file stack/.env.generated`; verify that compose merges multiple env files and record it).
4. Remove the temporary S2 mount of `dags/examples`. The examples project now loads as a bundle.
5. `scripts/up.ps1` calls `render` (through `stack up`). `stack status` gains `--projects PATH` and `--dags`; with `--dags`, the JSON gets `"dag_ids": [...]`, the active DAG ids from the REST API.
6. Restart the stack with the new config.

Tests (offline): `test_render_local_bundle_per_project`, `test_render_cloud_uses_git_bundle_and_skips_local_only`, `test_override_mounts_are_read_only`, `test_override_paths_use_forward_slashes`, `test_adding_a_project_changes_only_generated_output` (two registries in, two renders out, no code paths depend on the project names).
