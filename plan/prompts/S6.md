# S6: CI for python and the local stack

**Commands (permission rules):** run each command as a single `uv run ...` call. Don't use `&&`, `;`, pipes, PowerShell expressions, `uv lock`, `uv sync` or bare `python`/`pytest`. `uv run` locks and syncs by itself. Use: `uv run pytest -q`, `uv run python -m airflow_platform.stack ...`, `uv run python plan/accept/<script>.py`. Docker and Terraform go through the stack module or the acceptance scripts.

Contract: `docs/spec.md` §11 (python and stack jobs). Rules: `AGENTS.md`.

Build:
1. `.github/workflows/ci.yml`, on `push` and `pull_request`, `ubuntu-latest`, `permissions: contents: read`:
   - `python` job: `astral-sh/setup-uv` (pinned major), `uv sync --frozen`, `uv run pytest -q`.
   - `stack` job: checkout, setup-uv, then `pwsh scripts/up.ps1`. Use the examples project only: in CI, render with a `--projects` option pointing at `projects/ci.yaml`, which you create with just `examples`, because governor's paths don't exist in CI. Then `uv run python -m airflow_platform.stack status` (assert `import_errors == 0`), trigger `hello_workload`, `wait` (timeout 300) and assert `success`. Finally, always run `pwsh scripts/down.ps1 -Volumes`. On failure, upload `docker compose logs` as an artifact.
2. `stack.py`: a non-zero exit code when `wait` ends in any state other than `success`. (`--projects` already exists from S3.)
3. `scripts/ci-local.ps1`: runs the same stack-job sequence locally, so Amir can reproduce CI. It must **not touch the dev stack**: it uses compose project `airflow_platform_ci` and port 8081. Add `--compose-project` and `--port` options to `stack.py` (defaults `airflow_platform` / 8080) and pass them through every subcommand.

Tests (offline): `test_ci_workflow_has_jobs_python_and_stack`, `test_ci_has_no_secrets_reference` (no `secrets.` in the workflow), `test_actions_are_pinned` (every `uses:` has `@vN` or a SHA), `test_ci_registry_has_only_examples`.

Done when `plan/accept/accept_s6.py` passes. It runs `scripts/ci-local.ps1` (the same sequence as the CI stack job) and the static checks; GitHub itself runs only after Amir pushes.
