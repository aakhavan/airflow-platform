# S4: Project views plugin (external views and task links)

Contract: `docs/spec.md` §7 and §12 (S4 row). ADR 0003. Rules: `AGENTS.md`.

Build:
1. Read the Airflow 3.3 plugin docs ("Plugins" and "Custom view plugin"): the `external_views` keys (`name`, `href`, `destination`, `category`, `url_route`, `icon`), whether a `dag` destination can be limited to some DAGs, the `BaseOperatorLink` signature, `global_operator_extra_links`, and the REST route that lists plugins. Record the findings in `NOTES.md`.
2. `src/airflow_platform/views.py` (pure, no airflow import):
   - `views_for(projects) -> list[dict]`: a nav view (category `browse`) and a dag-tab view per project with `view`;
   - `link_for(project, dag_id, run_id, task_id) -> str`: formatted from `url_template` when `dag_id.startswith(dag_prefix)`, else `""`. Values are URL-quoted.
3. `plugins/project_views/__init__.py`: reads `/opt/airflow/projects/projects.yaml` (env override `PLATFORM_PROJECTS_FILE`) and builds `external_views` with the **same logic** as `views.py`. Copy the two functions into the plugin, or vendor `views.py` into `plugins/project_views/_views.py` with a test asserting the two copies are identical. Never install the host package into the Airflow image. For each project with a `task_link` it defines one `BaseOperatorLink` subclass and registers it through `global_operator_extra_links`. On any error reading or validating the file, it logs **one warning** and registers nothing.
4. Mount `plugins/` read-only at the plugins folder of the compose file (all Airflow services). Set `AIRFLOW__CORE__LAZY_LOAD_PLUGINS: "false"` if the docs advise it for UI plugins.
5. For the live check, `projects/projects.yaml` gets a `view` and a `task_link` on the `examples` project pointing to `http://localhost:8080/docs` (a page that exists). S5 replaces this with governor's.
6. `stack.py`: `plugins` prints the plugins REST route's JSON as one line; `links <dag_id> <run_id> <task_id>` prints `{"links": {name: url}, "source": "api"}` from the task instance extra-links route (verify it). If the release has no such route, compute the link with `views.link_for` and set `"source": "computed"`, and record that.
7. Restart the stack.

Tests (offline): `test_views_for_nav_and_dag_tab`, `test_link_for_matching_prefix`, `test_link_for_other_dag_is_empty`, `test_link_values_are_quoted`, `test_plugin_copy_matches_views_module`, `test_plugin_imports_only_allowed_modules` (AST: stdlib, yaml, airflow), `test_broken_registry_registers_nothing` (load the plugin module with a bad file and a stub `airflow` package in `sys.modules`).

Done when `plan/accept/accept_s4.py` passes. It reads the plugins route of the running server and checks the view names and hrefs, then triggers `hello_workload` and checks the run's task link through the REST API (verify the extra-links route) or, if no route exists, records that and checks the rendered link with `link_for`.
