# S1: Airflow image and the lean local stack

Contract: `docs/spec.md` §4 and §12 (S1 rows). Rules: `AGENTS.md` (thin-orchestrator rule).

Build:
1. Find the latest Airflow **3.3.x** patch (official release notes). Download that release's official `docker-compose.yaml` and save it as `stack/compose.yaml`, with a first comment line holding the URL and today's date. Then trim it as §4 says: LocalExecutor; drop redis, worker and flower; keep postgres, airflow-init, api-server, scheduler, dag-processor and triggerer; `LOAD_EXAMPLES` false; compose project name `airflow_platform`; UI port `${AIRFLOW_PORT:-8080}`; a healthcheck on every service; `image: airflow-platform:local` with `build: ../image`.
2. `image/Dockerfile`: `FROM apache/airflow:<version>-python3.12`. Install `image/requirements.txt` with `--constraint https://raw.githubusercontent.com/apache/airflow/constraints-<version>/constraints-3.12.txt`. Put the version in one `ARG`.
3. `image/requirements.txt`: providers only, unpinned (`apache-airflow-providers-docker`, `-standard`, `-git`, `-amazon`, `-google`). If amazon + google make the image too heavy (>2.5 GB), keep them out of the local image, add an `ARG CLOUD_PROVIDERS` that is off locally, and record the sizes.
4. `stack/.env.example`: variable names with the official local defaults only (the `AIRFLOW_UID` note, the admin login of the auth manager this release uses). `stack/versions.yaml`: the Airflow version, image tags, the compose source URL and date, the constraints URL and the image size.
5. `src/airflow_platform/stack.py`: `python -m airflow_platform.stack up|down|status` (`up` → `docker compose -p airflow_platform -f stack/compose.yaml [-f stack/compose.projects.yaml if present] --env-file stack/.env up -d --wait`; it copies `.env.example` to `.env` if `.env` is missing; `down` keeps volumes unless `--volumes`). `status` prints one JSON line last, as §4 says (`mem_mb` from `docker stats --no-stream`).
6. `scripts/up.ps1`, `down.ps1`, `status.ps1`: thin `pwsh` wrappers that call `uv run python -m airflow_platform.stack ...`.
7. Start the stack and leave it running for the next steps.

Tests (offline): `test_compose_has_no_celery_services`, `test_every_service_has_healthcheck`, `test_executor_is_local`, `test_dockerfile_installs_with_constraints`, `test_status_line_shape` (on a recorded `docker compose ps --format json` sample saved as a fixture).

Write the auth manager you found and its default login into `NOTES.md` (names, not passwords beyond the documented defaults).

Done when `plan/accept/accept_s1.py` passes (it needs the stack up).
