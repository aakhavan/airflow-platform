# S2: Workload pattern (socket proxy, hello workload, trigger and wait)

Contract: `docs/spec.md` §5 and §12 (S2 rows). ADR 0001. Rules: `AGENTS.md`.

Build:
1. `stack/compose.yaml`: add service `docker-proxy` (`tecnativa/docker-socket-proxy`, pinned tag, recorded in `versions.yaml`). It mounts `/var/run/docker.sock:ro` and is on the compose network only (no host port). Start with `CONTAINERS=1 IMAGES=1 POST=1` and add only the sections `DockerOperator` proves to need; record the final list and why in `NOTES.md`. **No Airflow service mounts the socket.**
2. `workloads/hello/Dockerfile` (`python:3.12-slim`, pinned) + `main.py`: prints `hello from a workload`, then one JSON line `{"workload":"hello","ok":true,"python":"3.12.x"}`, and exits 0. Built as `airflow-platform/hello:local` by `stack up` (add a `build` step for images under `workloads/`).
3. `dags/examples/hello_workload.py`: `dag_id="hello_workload"`, `schedule=None`, `catchup=False`, tags `["platform"]`. One `DockerOperator` task `hello`: `image="airflow-platform/hello:local"`, `docker_url` from the Variable `docker_url` (default `tcp://docker-proxy:2375`), `mount_tmp_dir=False`, `auto_remove="success"`. Import only airflow, providers and the stdlib.
4. Until S3 renders bundles, mount `dags/examples` into the DAG folder the compose file uses, so the DAG loads now. S3 replaces this mount.
5. `stack.py`: add `trigger <dag_id> [--conf JSON]` and `wait <dag_id> <run_id> [--timeout 300]` over the REST API v2. Get the token from the auth route of this release (find it on the running server's `/docs`; record it in `NOTES.md`); the token stays in memory. Each command prints one JSON line last: `{"dag_id","run_id","state"}`. Also add `logs <dag_id> <run_id> <task_id>`, which prints the last 20 lines of the task log.
6. `stack.py status` gains `"import_errors": int`, from `airflow dags list-import-errors -o json` in the scheduler container (verify the command).

Tests (offline): `test_hello_dag_imports_only_allowed_modules` (an AST scan of `dags/`), `test_no_airflow_service_mounts_docker_socket`, `test_trigger_payload_shape`, `test_wait_parses_states` (recorded API payload fixtures with ids removed).

Done when `plan/accept/accept_s2.py` passes. It triggers `hello_workload`, waits for success, finds the JSON line in the task log and checks the isolation denylist inside `airflow-platform:local`.
